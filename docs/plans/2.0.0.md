# java-sdk 2.0.0: idiomatic API

Status: owner decisions accepted 2026-11-17; implemented on `next/major`.

java-sdk is the reference implementation and the core that kotlin-sdk (an idiomatic Kotlin wrapper for any JVM,
servers and Android), android-sdk (built on kotlin-sdk) and scala-sdk wrap. 2.0 is where **all** breaking changes
live: the API is reshaped to read like modern Java (LaunchDarkly, Statsig, Optimizely and PostHog's Java SDKs are the
peers), while assignment, exposure, publish and refresh behaviour stays byte-for-byte the 1.x behaviour and the
cross-SDK contract (javascript-sdk is the contract reference; every cross-sdk-tests scenario must pass).

## Owner decisions

All accepted by the owner on 2026-11-17.

| # | Decision | Accepted |
|---|---|---|
| 1 | Platform floor | **Java 11** (no records, sealed types or pattern matching in the public API). Android consumes 2.x with core library desugaring. |
| 2 | Artifact | **Keep `com.absmartly.sdk:core-api`**, now at 2.x. `core-api-java6` is not continued in 2.x (1.x keeps it). |
| 3 | Package | **Keep `com.absmartly.sdk`.** 1.x and 2.x cannot share a classpath (same artifact id), so a `.v2` package buys nothing. |
| 4 | Events | **A typed listener** (`client.onEvent(...)`, `context.onEvent(...)`, typed event classes) **plus a `java.util.concurrent.Flow.Publisher<ContextEvent>`** (`events()`). |
| 5 | JSON | **Jackson stays, shaded and relocated** to `com.absmartly.sdk.internal.shaded.jackson`. It never conflicts with the user's Jackson and no Jackson type is in the public API. |
| 6 | Async | **Keep blocking + `...Async` (`CompletableFuture`) pairs** for context creation, `publish`, `refresh` and `close`. |
| 7 | Naming | Brand spelling `ABsmartly` (`ABsmartlyClient`); records-style accessors (`units()`, not `getUnits()`). |
| 8 | Lifecycle | 1.x moves to `release/1.x` when 2.0 merges and gets bug fixes for 12 months (see `SUPPORT.md`). No compat shim: `MIGRATING.md` only. |
| 9 | Transport | `java.net.http.HttpClient` is the default behind a `Transport` interface, in a class Android never loads (see Platform). |

## Goals and non-goals

- One entry point, one immutable options type per scope, structured state, typed variables, typed errors and typed
  events.
- Nothing in the public API that a Kotlin or Scala layer has to undo: JSpecify nullability everywhere
  (`@NullMarked` packages, explicit `@Nullable`), no checked exceptions, immutable value types, `CompletableFuture`
  for I/O, synchronous thread-safe reads.
- **No behaviour change.** Hashing, variant assignment, audiences, assignment rules, holdouts, switchbacks, exposure
  de-duplication, publish batching, retry and refresh are the 1.x engine, moved, not rewritten. The 1.x unit suite is
  ported 1:1 (only call sites renamed) and the cross-sdk-tests suite runs against both lines.
- Not in 2.0: a Spring Boot starter (a separate optional artifact later), a compat shim.

## API before and after

| Area | 1.x | 2.0 |
|---|---|---|
| Entry point | `ABSmartly.create(ABSmartlyConfig.create().setClient(Client.create(ClientConfig.create().setEndpoint(e)...)))` or `ABSmartly.builder()` | `ABsmartlyClient.builder().endpoint(URI.create(e)).apiKey(k).application(a).environment(env).build()` |
| Config types | `ABSmartlyConfig`, `ClientConfig`, `Client`, `DefaultHTTPClientConfig` (mutable, setters) | `ABsmartlyClient.Builder` (+ `JdkHttpTransport.Builder` for HTTP tuning) |
| HTTP | `HTTPClient` + Apache HttpClient 5 `DefaultHTTPClient` | `Transport` + `JdkHttpTransport` (`java.net.http`): the 1.x retry policy (5 retries on 502/503, dropped connections and connect timeouts; no retry on a refused connection; same back-off) and redirects (followed, never https to http) |
| Context options | `ContextConfig.create().setUnit(...).setAttribute(...)` (mutable) | `ContextOptions.builder().unit(...).attribute(...).build()` (immutable) |
| Create, block | `sdk.createContext(cfg).waitUntilReady()` (a failed load still returns) | `client.context(options)` returns a ready context or throws `ContextLoadException` |
| Create, async | `sdk.createContext(cfg).waitUntilReadyAsync()` | `client.contextAsync(options)` (`CompletableFuture<Context>`, fails with `ContextLoadException`) |
| Create, not awaited | `sdk.createContext(cfg)` | `client.newContext(options)`, then `context.ready()` / `context.readyAsync()` |
| Prefetched data | `sdk.createContextWith(cfg, data)` / `sdk.getContextData()` (Jackson model) | `client.context(options, data)` / `client.contextData()` (opaque `ContextData` with `toJson()`/`fromJson()`) |
| State | `isReady() isFailed() isClosing() isClosed() isFinalizing() isFinalized()` | `state()` → `ContextState { LOADING, READY, FAILED, CLOSING, CLOSED }`, `failure()` |
| Load error | `readyError()` | `failure()` (`@Nullable Throwable`) |
| Treatment | `getTreatment(e)` / `peekTreatment(e)` | `treatment(e)` / `peekTreatment(e)` |
| Variables | `Object getVariableValue(k, Object def)` | `<T> T variable(k, T def)` (typed by the default), `<T> T variable(k, Class<T>, T def)` (maps JSON objects to your type), untyped `variableValue(k, def)`; `peekVariable…` twins |
| Variable keys | `getVariableKeys()` | `variableKeys()` |
| Experiments | `String[] getExperiments()` | `List<String> experiments()` |
| Custom fields | `getCustomFieldKeys()`, `getCustomFieldValue(e, k)`, `getCustomFieldValueType(e, k)` | `customFieldKeys()`, `customFieldValue(e, k)`, `customFieldType(e, k)` |
| Units | `setUnit`, `setUnits`, `getUnit`, `getUnits`, `getUnitValue(s)` | `setUnit`, `setUnits`, `unit(t)`, `units()` |
| Attributes | `setAttribute(s)`, `getAttribute`, `getAttributes` | `setAttribute(s)`, `attribute(n)`, `attributes()` |
| Overrides | `setOverride(s)`, `getOverride` | `setOverride(s)`, `override(e)`, `overrides()`, `clearOverride(e)` |
| Custom assignments | `setCustomAssignment(s)`, `getCustomAssignment` | `setCustomAssignment(s)`, `customAssignment(e)`, `customAssignments()`, `clearCustomAssignment(e)` |
| Goals | `track(goal, Map<String, Object>)` | `track(goal)`, `track(goal, Map<String, ?>)` |
| Publish / refresh / close | `publish()`/`publishAsync()`, `refresh()`/`refreshAsync()`, `close()`/`closeAsync()`, `finalizeAsync()` | same pairs; `finalize*` removed; blocking twins throw the unwrapped `ABsmartlyException` instead of `CompletionException` |
| Pending | `getPendingCount()` | `pendingEventCount()` |
| Data | `getData()` (Jackson model) | `data()` (opaque `ContextData`) |
| Events | `ContextEventLogger.handleEvent(Context, EventType, Object)` | `EventListener.onEvent(ContextEvent)`; `ReadyEvent`, `RefreshEvent`, `ExposureEvent`, `GoalEvent`, `PublishEvent`, `CloseEvent`, `ErrorEvent`, each with `type()` for a Java 11 `switch`; `events()` → `Flow.Publisher<ContextEvent>` |
| Errors | `IllegalStateException`, `IllegalArgumentException`, raw `Exception(statusMessage)` in `CompletionException` | unchecked `ABsmartlyException` root: `ContextNotReadyException`, `ContextClosedException`, `ContextLoadException`, `UnitAlreadySetException`, `HttpStatusException(statusCode)`, `RequestTimeoutException`, `DecodingException`. Bad arguments stay `IllegalArgumentException`. |
| Customisation seams | `ContextDataProvider`, `ContextEventHandler`, `VariableParser`, `AudienceDeserializer`, `ContextDataDeserializer`, `ContextEventSerializer` | `Transport` (the one seam: tests, proxies, OkHttp on Android). The rest are internal. |

### Example

```java
// 1.x
ABSmartly sdk = ABSmartly.create(ABSmartlyConfig.create().setClient(Client.create(ClientConfig.create()
        .setEndpoint("https://acme.absmartly.io/v1").setAPIKey(key)
        .setApplication("website").setEnvironment("production"))));
Context context = sdk.createContext(ContextConfig.create().setUnit("session_id", sid)).waitUntilReady();
if (context.isFailed()) { ... }
String color = (String) context.getVariableValue("button.color", "blue");
context.close();

// 2.0
try (ABsmartlyClient client = ABsmartlyClient.builder()
        .endpoint(URI.create("https://acme.absmartly.io/v1")).apiKey(key)
        .application("website").environment("production")
        .build();
        Context context = client.context(ContextOptions.builder().unit("session_id", sid).build())) {
    int variant = context.treatment("exp_checkout");
    String color = context.variable("button.color", "blue");
    CheckoutConfig cfg = context.variable("checkout", CheckoutConfig.class, CheckoutConfig.DEFAULT);
    context.track("purchase", Map.of("total", 19.99));
}   // close() publishes pending events

client.onEvent(event -> {
    switch (event.type()) {                       // Java 11: switch on the type enum, then cast
    case EXPOSURE:
        ExposureEvent exposure = (ExposureEvent) event;
        analytics.track(exposure.exposure().name(), exposure.exposure().variant());
        break;
    case ERROR:
        log.warn("absmartly", ((ErrorEvent) event).cause());
        break;
    default:
    }
});
// On Java 16+ user code can write `if (event instanceof ExposureEvent e)`; the SDK itself needs only Java 11.
```

### Kotlin and Scala on top

- Every public package is `@NullMarked` (JSpecify); `@Nullable` marks the few nullable results (`unit(t)`,
  `attribute(n)`, `override(e)`, `failure()`, `variableValue(k, def)`). Kotlin sees `String` / `String?`, not
  platform types. `@Nullable` is preferred over `Optional` because Kotlin maps it to `T?` for free.
- kotlin-sdk turns `contextAsync` into a `suspend fun` (`await()`), `onEvent` into a `callbackFlow` / `SharedFlow`,
  and `state()` into a `StateFlow` updated from the `ReadyEvent`/`ErrorEvent`/`CloseEvent` stream.
- scala-sdk wraps `CompletableFuture` with `FutureConverters` and `EventListener` as a function.
- Value types (`ContextOptions`, `Exposure`, `Goal`, the events) are final and immutable; their accessors are
  records-style so a later move to records (Java 16+) is source compatible.

## Platform floor and why

- **Java 11** (owner decision): the oldest LTS the JVM ecosystem still widely runs and the first with
  `java.net.http`, `Flow` and `CompletableFuture` improvements; Java 17 would exclude a measurable set of server users
  for no API gain we use (records/sealed are not allowed in the public API anyway, to keep Android desugaring simple).
- **Android**: kotlin-sdk (and through it android-sdk) consumes core-api 2.x. The Android check (Animal Sniffer,
  `android-api-level-24` signature) still runs on the core sources; `java.time` (`Duration`, `Instant`) is ignored by
  that check because core library desugaring provides it. `java.net.http` is not on Android at all, so
  `JdkHttpTransport` is compiled from a separate source set (`src/jdk`) that Animal Sniffer does not check and that
  no core class references: `ABsmartlyClient` loads it reflectively only when the caller did not supply a
  `Transport`. Android callers always supply one (kotlin-sdk ships an `HttpURLConnection`/OkHttp transport), so ART
  never loads the class. `Context.events()` returns `Flow.Publisher` (Android API 30+); its implementation lives in
  its own class that is loaded only when `events()` is called, so `onEvent` is the Android path below API 30.
- CI builds on JDK 11 (the floor) and tests on 11, 21 and 25.

## Dependencies

| 1.x | 2.0 |
|---|---|
| `org.apache.httpcomponents.client5:httpclient5` + `httpclient5-fluent` 5.1.3 | removed (JDK `HttpClient`) |
| `jackson-databind` 2.13.4.2 + `jackson-datatype-jsr310` (unused) | `jackson-databind` 2.13.5 **shaded and relocated** into the jar (kept on 2.13 for the Android API 24 baseline; Jackson 2.14+ needs API 26). jsr310 dropped. |
| `jsr305` 3.0.2, `findbugs-annotations` 3.0.1 (both dead) | `org.jspecify:jspecify` 1.0.0 (the only annotation dependency; tiny, no runtime code) |
| `slf4j-api` 1.7.30 | `slf4j-api` 2.0.x (API-compatible for callers; bindings: any SLF4J 2 provider) |
| `streamsupport-minifuture` (java6 artifact) | gone with `core-api-java6` |

The published POM lists only `slf4j-api` and `jspecify`. A build check fails if any unrelocated `com/fasterxml`
class ends up in the jar.

JPMS: the jar carries `Automatic-Module-Name: com.absmartly.sdk`.

## Behaviour parity

- The `Context` engine (assignment cache, holdouts, switchbacks, exposure queue, publish/close state machine) is the
  1.x code with only public method names changed. The 1.x unit tests are ported with renamed call sites and keep the
  same assertions (752 tests on 1.9.0+main); new tests cover the new surface (typed variables, state, events, errors,
  transport).
- `ContextEventLogger` semantics map 1:1 onto events: the same event kinds, fired at the same points with the same
  data. One deliberate difference: an exception thrown by a user `EventListener` is caught and logged instead of
  propagating into `treatment()`/`track()`. The engine paths that tolerate a throwing logger are kept and still
  tested through the internal seam.
- Wire format: unchanged (`PUT {endpoint}/context`, same headers: `X-API-Key`, `X-Application`, `X-Environment`,
  `X-Application-Version`, `X-Agent: absmartly-java-sdk/2.0.0`, same JSON).
- Proof: the ported unit suite, a local-HTTP-server integration test through `JdkHttpTransport`, and the
  cross-sdk-tests `java` lane (2.0 wrapper) next to the `java-v1` lane (1.x wrapper).

## Coexistence with 1.x

- `main` becomes 2.x when this PR merges (tags `v2.*`). `release/1.x` is cut by the owner from the last 1.x tag and
  gets bug fixes for 12 months (`SUPPORT.md`). Fix flow: fix on `main`, cherry-pick to `release/1.x`.
- CI (`main.yml`) runs on push and PR for `main` and `release/**`; `publish.yml` publishes on `v*` tags and fails
  if the tag does not equal `VERSION`. The same workflow files must be added to `release/1.x` once it is cut (a
  separate small PR).
- Maven Central: versions coexist, nothing special. GitHub releases for `v1.*` tags are created with
  `--latest=false` so a 1.x patch never becomes "latest".
- cross-sdk-tests: the `java` lane is pinned to `next/major` (then `main`), and a new `java-v1` lane runs the 1.x
  wrapper against `release/1.x` (until it exists: the last 1.x commit on `main`).

## Migration

See `MIGRATING.md` for the 1:1 table with before/after snippets. In short: replace the config objects with the two
builders, `createContext(...).waitUntilReady()` with `client.context(options)`, `get*` accessors with their noun
forms, the `is*` booleans with `state()`, casts of `getVariableValue` with `variable(key, default)`, and
`ContextEventLogger` with `onEvent`.
